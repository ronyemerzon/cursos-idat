1. Introducción y Contexto de la Problemática

Actualmente, muchas instituciones educativas se enfrentan a procesos manuales y descentralizados para la administración de asignaturas y alumnos, careciendo de un control de acceso por perfiles que garantice la integridad de la información. Los administradores deben consultar diferentes fuentes de datos, lo que entorpece la experiencia de usuario y pone en riesgo la seguridad institucional.

Para resolver esta problemática se desarrolló EduPortal, una solución web SPA construida con el framework Angular y respaldada por una API REST en Java Spring Boot 3 conectada a Microsoft SQL Server. El sistema integra autenticación basada en JSON Web Token (JWT), enrutamiento protegido mediante Guards y carga dinámica de componentes (Lazy Loading) según los roles: Administrador, Docente y Estudiante.

3. Implementación de Guards de Autenticación y Autorización

Se implementaron tres guards funcionales de tipo CanActivateFn para controlar el acceso a nivel de enrutamiento:

  • authGuard: Valida si existe un token JWT válido y no caducado en el localStorage. Si no existe, almacena la URL de destino en returnUrl y redirige al usuario a /login.
  • roleGuard: Evalúa si el rol del usuario autenticado coincide con los roles requeridos en la propiedad data: { roles: [...] } de la ruta. Si el rol es insuficiente, redirige de inmediato a /unauthorized con una notificación de denegación de permisos.
  • loginGuard: Previene que un usuario con sesión activa regrese accidentalmente a la pantalla de login, redirigiéndolo al /dashboard.

Fragmento de Código: role.guard.ts

export const roleGuard: CanActivateFn = (route: ActivatedRouteSnapshot) => {
  const authService = inject(AuthService);
  const router = inject(Router);
  const notification = inject(NotificationService);

  if (!authService.isAuthenticated()) {
    notification.warning('Acceso Restringido', 'Inicia sesión para continuar.');
    return router.createUrlTree(['/login']);
  }

  const expectedRoles = route.data['roles'] as Array<string>;
  const userRole = authService.getUserRole();

  if (userRole && authService.hasRole(expectedRoles)) {
    return true; // Acceso autorizado
  }

  notification.error('Permiso Denegado', 'No cuentas con privilegios suficientes.');
  return router.createUrlTree(['/unauthorized']);
};

4. Consumo de Servicios REST con JWT e Interceptores

La comunicación con el backend Spring Boot se realiza mediante HttpClient y Observables RxJS organizados en servicios especializados por entidad:

Servicio Angular Método HTTP Endpoint REST Descripción
AuthService POST /api/auth/login Envía credenciales y recibe el token JWT firmado.
AuthService GET /api/auth/me Obtiene los datos del usuario autenticado en sesión.
UserService GET /api/users Listado de usuarios con filtros de búsqueda por nombre/correo.
UserService POST /api/users Crea un nuevo usuario en la base de datos SQL Server.
UserService PUT /api/users/:id Actualiza información, rol y teléfono del usuario.
UserService DELETE /api/users/:id Elimina físicamente el registro de un usuario.
UserService PATCH /api/users/:id/toggle-status Alterna el estado del usuario entre ACTIVO e INACTIVO.
CourseService GET /api/courses Catálogo de cursos con soporte de filtros por categoría.
CourseService GET /api/courses/:id Obtiene detalle, ficha técnica y syllabus de una asignatura.
CourseService POST /api/courses/:id/enroll Matricula a un estudiante y valida la disponibilidad de vacantes.

Interceptores Configurados en Cadena (app.config.ts):

  1. jwtInterceptor: Inyecta automáticamente el encabezado Authorization: Bearer <token> en cada solicitud saliente hacia la API.
  2. errorInterceptor: Captura globalmente códigos de error HTTP 401 (deslogueo automático por expiración), 403 (redirección a vista de acceso denegado) y 500.
  3. apiFallbackInterceptor: Garantiza resiliencia y disponibilidad continua de datos locales en caso de desconexión del servidor.
